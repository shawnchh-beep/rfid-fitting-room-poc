

拖拉路徑與事件規則表 v1.0

1. 目的

定義 RFID Fitting Room Demo 中，商品在各區域間拖拉時的：
	•	合法路徑
	•	系統事件
	•	資料更新規則
	•	UI 顯示規則
	•	限制條件

本版本以 受控式拖拉流程 為原則，不支援完全自由拖拉。

⸻

2. 區域定義

2.1 Rack

代表門市展示區 / 貨架區。
狀態意義：
	•	商品可被拿去試穿
	•	商品可直接購買
	•	商品試穿後可回到此區

⸻

2.2 Fitting Room

代表試衣間區域。
本版本預設：
	•	Room 1
	•	Room 2
	•	Room 3
	•	Room 4

每個 room 為獨立 drop zone。

⸻

2.3 Checkout

代表結帳區。
用途：
	•	試穿後購買
	•	未試穿直接購買

⸻

3. 商品狀態定義

狀態值	說明
on_floor	商品在 Rack，可試穿或直接購買
in_room	商品目前在試衣間
sold	商品已成交，不可再拖動


⸻

4. 合法拖拉路徑總表

路徑	是否允許	商業意義	是否建立 Session
Rack → Fitting Room	Yes	商品進入試衣間	Yes
Fitting Room → Rack	Yes	試穿後未購買，回到貨架	Yes
Fitting Room → Checkout	Yes	試穿後購買	Yes
Rack → Checkout	Yes	未試穿直接購買	No
Rack → Rack	No	無意義	No
Checkout → Rack	No	成交後不可回流	No
Checkout → Fitting Room	No	成交後不可再試穿	No
Fitting Room → Fitting Room	No（v1）	暫不支援換房	No


⸻

5. 路徑事件規則

5.1 Rack → Fitting Room

觸發條件

使用者將 on_floor 狀態商品從 Rack 拖入某個 Fitting Room。

系統動作
	1.	建立 enter_room event
	2.	建立一筆新的 fitting session
	3.	更新 item 狀態為 in_room
	4.	記錄：
	•	entered_at
	•	room_id
	•	session_status = in_room

資料更新

Event
	•	event_type = enter_room

Session
	•	session_status = in_room
	•	entered_at = now
	•	exited_at = null
	•	is_converted = false

Item
	•	status = in_room

UI 反應
	•	商品從 Rack 消失
	•	商品顯示在對應 Room 內
	•	Room occupancy +1
	•	Recent Events 顯示一筆進房事件

⸻

5.2 Fitting Room → Rack

觸發條件

使用者將 in_room 狀態商品從某個 Fitting Room 拖回 Rack。

系統動作
	1.	建立 exit_room event
	2.	更新對應 fitting session
	3.	記錄：
	•	exited_at
	•	dwell_seconds
	•	session_status = exited
	4.	若有 active alert，可同步標記 resolved
	5.	更新 item 狀態為 on_floor

資料更新

Event
	•	event_type = exit_room

Session
	•	session_status = exited
	•	exited_at = now
	•	dwell_seconds = exited_at - entered_at
	•	is_converted = false

Item
	•	status = on_floor

UI 反應
	•	商品從 Room 移除
	•	商品回到 Rack
	•	Room occupancy -1
	•	Recent Events 顯示一筆離房事件

⸻

5.3 Fitting Room → Checkout

觸發條件

使用者將 in_room 狀態商品從某個 Fitting Room 拖入 Checkout。

系統動作
	1.	建立 exit_room event
	2.	建立 sale_completed event
	3.	更新對應 fitting session
	4.	記錄：
	•	exited_at
	•	dwell_seconds
	•	is_converted = true
	•	session_status = purchased
	5.	建立 sale record
	6.	更新 item 狀態為 sold

資料更新

Event
	•	event_type = exit_room
	•	event_type = sale_completed

Session
	•	session_status = purchased
	•	exited_at = now
	•	dwell_seconds = exited_at - entered_at
	•	is_converted = true

Sale
	•	sale_type = try_on_purchase

Item
	•	status = sold

UI 反應
	•	商品從 Room 移除
	•	商品顯示在 Checkout / Purchased 區
	•	Room occupancy -1
	•	KPI 中 try-on purchase +1
	•	Recent Events 顯示離房與成交事件

⸻

5.4 Rack → Checkout

觸發條件

使用者將 on_floor 狀態商品從 Rack 直接拖入 Checkout。

系統動作
	1.	建立 direct_sale event
	2.	建立 sale record
	3.	不建立 fitting session
	4.	更新 item 狀態為 sold

資料更新

Event
	•	event_type = direct_sale

Session
	•	不建立

Sale
	•	sale_type = direct_purchase
	•	try_on_flag = false

Item
	•	status = sold

UI 反應
	•	商品從 Rack 消失
	•	商品顯示在 Checkout / Purchased 區
	•	KPI 中 direct purchase +1
	•	不計入 try-on conversion

⸻

6. 非法拖拉規則

6.1 Rack → Rack

規則

不處理，不產生事件。

UI
	•	放下後回彈原位

⸻

6.2 Checkout → 任何區域

規則

不允許，成交商品不可回流。

UI
	•	顯示不可放置狀態
	•	放下後回彈原位

⸻

6.3 Fitting Room → Fitting Room

規則

v1 不支援換房，避免 session 複雜化。

UI
	•	放下後回彈原位

⸻

7. Session 規則

7.1 何時建立 Session

只有在 Rack → Fitting Room 時建立 session。

⸻

7.2 何時結束 Session

以下情況結束 session：
	•	Fitting Room → Rack
	•	Fitting Room → Checkout

⸻

7.3 哪些流程不建立 Session
	•	Rack → Checkout

⸻

8. Event Type 定義

event_type	說明
enter_room	商品進入試衣間
exit_room	商品離開試衣間
sale_completed	試穿後完成購買
direct_sale	未試穿直接購買
alert_triggered	超時或異常警示觸發
alert_resolved	警示解除


⸻

9. Alert 規則

9.1 觸發條件

當商品處於 in_room 狀態超過設定 threshold 時：
	•	建立 alert_triggered
	•	session 可標記為 overdue

⸻

9.2 解除條件

以下任一情況可解除 alert：
	•	商品從 Room 拖回 Rack
	•	商品從 Room 拖到 Checkout
	•	手動執行 Resolve Alert

⸻

10. KPI 計算規則

KPI	計算方式
Total Try-Ons	enter_room 次數或 session 數量
Try-On Purchases	sale_completed 數量
Direct Purchases	direct_sale 數量
Conversion Rate	Try-On Purchases / Total Try-Ons
Avg Dwell Time	已結束 session 的平均 dwell_seconds
Active Overdue Items	當前 active alert 數量


⸻

11. Drop Zone 行為規則

11.1 Rack

可接收來源：
	•	Fitting Room

不可接收來源：
	•	Checkout

⸻

11.2 Fitting Room

可接收來源：
	•	Rack

不可接收來源：
	•	Checkout
	•	其他 Fitting Room（v1）

⸻

11.3 Checkout

可接收來源：
	•	Rack
	•	Fitting Room

⸻

12. UI 互動規則

12.1 拖曳開始
	•	高亮可合法放置的 drop zones
	•	不合法區域不高亮

12.2 拖曳中
	•	顯示 ghost / drag preview
	•	drop zone 顯示 hover state

12.3 放下成功
	•	先執行資料更新
	•	成功後更新 UI
	•	顯示 toast：
	•	Item entered fitting room
	•	Item returned to rack
	•	Purchase completed
	•	Direct purchase completed

12.4 放下失敗
	•	item 回彈
	•	顯示簡短提示：
	•	Invalid move
	•	This item cannot be dropped here

⸻

13. v1 限制範圍

本版不支援：
	•	Room to Room transfer
	•	多商品一次拖動
	•	同一商品重複開啟多個 active session
	•	成交後回流
	•	自由空間定位
	•	非受控拖拉行為

15. 一句話版結論

v1 拖拉流程只支援 4 條核心合法路徑：
	•	Rack → Fitting Room
	•	Fitting Room → Rack
	•	Fitting Room → Checkout
	•	Rack → Checkout

其中只有進入試衣間的流程會建立 fitting session，
Rack → Checkout 視為 direct purchase，不納入 try-on conversion。
