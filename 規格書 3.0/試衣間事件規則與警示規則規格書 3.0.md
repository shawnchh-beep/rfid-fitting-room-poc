



1. 文件目的

本文件用於定義 RFID 試衣間 Demo 系統中的：
	•	事件種類
	•	事件觸發條件
	•	狀態流轉規則
	•	Session 建立與結束規則
	•	停留時間計算規則
	•	警示觸發條件
	•	Demo 模式與未來實際整合模式的共用邏輯

本文件是以下工作的基礎：
	•	Event engine 開發
	•	Session builder 開發
	•	Alert engine 開發
	•	KPI aggregation 開發
	•	AI insight engine 開發
	•	UI 畫面即時事件流顯示

⸻

2. 設計原則

2.1 核心聚焦

本版本聚焦於：
	•	商品進入試衣間
	•	商品離開試衣間
	•	商品離開後去向
	•	試衣停留時間
	•	試衣結果與警示

2.2 不作為核心必要條件

以下能力不屬於本版本事件主邏輯前提：
	•	商品精準離開貨架偵測
	•	全店即時 item-level 路徑追蹤
	•	顧客身份辨識
	•	顧客與商品的一對一綁定

2.3 規則引擎優先

本版本先以 rule-based engine 為主。
AI 可讀取規則引擎產出的結果，但不直接取代事件判斷。

2.4 同時支援三種來源

所有事件規則需能支援：
	•	simulation
	•	ui_manual
	•	integration

⸻

3. 核心概念定義

3.1 Item

一件可被 RFID 追蹤的單品，對應唯一 EPC。

3.2 Fitting Session

一次試衣間內的試衣活動，通常由：
	•	一個 fitting room
	•	一段連續時間
	•	一組商品進出行為

所構成。

3.3 Event

商品或 session 發生的明確行為記錄。

3.4 Alert

當某事件或狀態符合規則門檻時，系統產生的提醒訊號。

7. 事件欄位最低要求

所有事件至少包含以下欄位：

欄位	說明
event_id	事件唯一 ID
event_type	事件類型
event_time	事件時間
store_id	門市 ID
item_id	商品 item ID，可為 null，若是 session 類事件可選填
epc	EPC，可為 null
sku_id	SKU，可為 null
fitting_room_id	試衣間 ID，可為 null
session_id	Session ID，可為 null
zone_from_id	來源區域，可為 null
zone_to_id	去向區域，可為 null
source_type	simulation / ui_manual / integration
raw_payload	原始資料，可為 null

8. Item 事件規則

⸻

8.1 item_entered_fitting_room

定義

商品被偵測進入某個試衣間。

觸發條件

符合以下任一條件即可觸發：

simulation
	•	模擬器自動將商品移入 fitting room

ui_manual
	•	使用者手動將商品拖入 fitting room 區域

integration
	•	試衣間 reader / sensor 偵測到該 EPC 進入試衣間區域

必填欄位
	•	event_type
	•	event_time
	•	store_id
	•	item_id
	•	epc
	•	sku_id
	•	fitting_room_id
	•	zone_to_id
	•	source_type

狀態變更

Item：
	•	current_status → in_fitting_room
	•	current_zone_id → fitting room zone

Session 規則
	•	若該 fitting room 當下沒有 active session，需建立新 session
	•	若已有 active session，商品加入既有 session

後續動作
	•	產生 item_added_to_session
	•	若新建 session，同步產生 session_started

⸻

8.2 item_added_to_session

定義

商品被納入某次 fitting session。

觸發條件
	•	在 item_entered_fitting_room 後，系統確認該商品歸屬某個 session

必填欄位
	•	event_type
	•	event_time
	•	item_id
	•	sku_id
	•	fitting_room_id
	•	session_id

資料更新

建立或更新 SessionItem：
	•	entered_at = event_time
	•	session_id
	•	item_id
	•	epc
	•	sku_id

⸻

8.3 item_left_fitting_room

定義

商品離開試衣間區域。

觸發條件

符合以下任一條件：

simulation
	•	模擬器將商品從 fitting room 移出

ui_manual
	•	使用者將商品拖出 fitting room

integration
	•	該 EPC 不再被 fitting room 區域持續偵測，且被判定離開區域

必填欄位
	•	event_type
	•	event_time
	•	item_id
	•	epc
	•	sku_id
	•	fitting_room_id
	•	session_id

狀態變更

Item：
	•	current_status → left_fitting_room

SessionItem 更新
	•	exited_at = event_time
	•	item_dwell_seconds = exited_at - entered_at

注意

item_left_fitting_room 只代表離開試衣間，不代表最終結果。
之後仍需依實際去向再產生：
	•	item_returned_to_floor
或
	•	item_moved_to_checkout

⸻

8.4 item_returned_to_floor

定義

商品離開試衣間後，被放回展示區 / 貨架區。

觸發條件
	•	商品從 fitting room 移動到 display area

必填欄位
	•	event_type
	•	event_time
	•	item_id
	•	sku_id
	•	session_id
	•	zone_to_id

狀態變更

Item：
	•	current_status → returned_to_floor
	•	current_zone_id → display area

SessionItem 更新
	•	exit_result = returned

Outcome 更新

建立 ItemOutcome：
	•	outcome_type = returned

⸻

8.5 item_moved_to_checkout

定義

商品離開試衣間後，被帶往結帳區。

觸發條件
	•	商品從 fitting room 移動到 checkout 區域

必填欄位
	•	event_type
	•	event_time
	•	item_id
	•	sku_id
	•	session_id
	•	zone_to_id

狀態變更

Item：
	•	current_status → moved_to_checkout
	•	current_zone_id → checkout

SessionItem 更新
	•	exit_result = checkout

Outcome 更新

建立 ItemOutcome：
	•	outcome_type = checkout

⸻

8.6 item_sold

定義

商品完成銷售。

觸發條件

simulation
	•	模擬器標記該商品成交

ui_manual
	•	使用者手動點選成交

integration
	•	POS / transaction 資料對應成功

必填欄位
	•	event_type
	•	event_time
	•	item_id 或 sku_id
	•	store_id
	•	session_id 可為 null，但建議有

狀態變更

Item：
	•	current_status → sold
	•	inventory_status → sold

Outcome 更新

若已有 checkout outcome，可更新為：
	•	outcome_type = sold

若無，則新增：
	•	outcome_type = sold

9. Session 規則

⸻

9.1 session_started

定義

某個 fitting room 開始一段新的試衣活動。

觸發條件
	•	第一件商品進入某個 fitting room，且目前沒有 active session

必填欄位
	•	event_type
	•	event_time
	•	store_id
	•	fitting_room_id
	•	session_id

資料更新

建立 FittingSession：
	•	session_status = active
	•	started_at = event_time
	•	item_count 初始為 0，後續依 SessionItem 更新

⸻

9.2 Session 加入規則

當 item_entered_fitting_room 發生時，系統應判斷：

若 fitting room 無 active session
	•	建立新 session

若 fitting room 有 active session
	•	商品加入既有 session

可設定的時間窗

未來若要更精細，可增加：
	•	若試衣間已超過無活動時間門檻，則自動關閉舊 session 並開新 session

本版 v1.0 建議簡化為：
	•	同一 fitting room 同時只允許一個 active session

⸻

9.3 session_completed

定義

一次試衣 session 正式結束。

觸發條件

符合以下任一條件即可：

規則 A
	•	該 session 所有商品皆已離開試衣間

規則 B
	•	最後一件商品離開後，超過 session_idle_close_seconds 仍無新商品進入

規則 C
	•	手動結束

建議預設值
	•	Demo mode：60 秒
	•	Realistic mode：300 秒

必填欄位
	•	event_type
	•	event_time
	•	session_id
	•	fitting_room_id

資料更新

FittingSession：
	•	session_status = completed
	•	ended_at = event_time
	•	dwell_seconds = ended_at - started_at
	•	更新：
	•	item_count
	•	converted_item_count
	•	returned_item_count
	•	moved_to_checkout_count
	•	outcome_type

outcome_type 規則
	•	若全部 returned → non_converted
	•	若全部 sold / checkout → converted
	•	若部分成交部分回架 → partial_converted

⸻

9.4 session_abandoned

定義

Session 被判定異常中止或放棄。

觸發條件

可選擇性支援，v1.0 可先保留：
	•	試衣間長時間無明確結束訊號
	•	商品長時間留在 room 中未處理
	•	手動標記放棄

資料更新

FittingSession：
	•	session_status = abandoned

⸻

10. 停留時間計算規則

⸻

10.1 Item dwell time

每件商品的停留時間計算方式：

item_dwell_seconds = SessionItem.exited_at - SessionItem.entered_at

若尚未離開：
	•	可用即時計算：
current_time - entered_at

⸻

10.2 Session dwell time

整個 session 停留時間：

session_dwell_seconds = session.ended_at - session.started_at

若 session 尚未結束：
	•	即時值為：
current_time - started_at

13. 警示規則明細

⸻

13.1 long_dwell

定義

某件商品在試衣間停留時間超過設定門檻。

scope_type
	•	item

觸發條件
	•	商品狀態為 in_fitting_room
	•	current_time - SessionItem.entered_at > threshold_seconds

建議門檻
	•	Demo mode：60 秒
	•	Retail realistic mode：900 秒 或 1800 秒

觸發結果

建立 Alert：
	•	alert_type = long_dwell
	•	item_id
	•	sku_id
	•	session_id
	•	fitting_room_id
	•	severity = warning

範例 message
	•	Item has stayed in fitting room longer than expected.
	•	Extended dwell may indicate customer hesitation or need for assistance.

⸻

13.2 item_left_in_room

定義

商品在 session 結束後，仍留在試衣間未被移出。

scope_type
	•	item
或
	•	session

觸發條件

符合以下條件：
	•	session 已完成或接近完成
	•	item 仍停留於 fitting room zone
	•	超過 room_clearance_threshold_seconds

建議門檻
	•	Demo mode：30 秒
	•	Realistic mode：300 秒

觸發結果

建立 Alert：
	•	alert_type = item_left_in_room
	•	severity = warning 或 critical

範例 message
	•	Item remains in fitting room after session end.
	•	Staff may need to recover the product.

⸻

13.3 long_session

定義

整體試衣 session 持續過久。

scope_type
	•	session

觸發條件
	•	session_status = active
	•	current_time - started_at > threshold_seconds

建議門檻
	•	Demo mode：120 秒
	•	Realistic mode：1200 秒 或 1800 秒

觸發結果

建立 Alert：
	•	alert_type = long_session

範例 message
	•	Fitting session duration is longer than normal.
	•	Consider staff support or operational review.

⸻

13.4 low_conversion_pattern

定義

某商品在一定期間內出現高試穿低成交型態。

scope_type
	•	sku
或
	•	style

觸發條件

例如：
	•	try_on_count >= min_try_on_threshold
	•	conversion_rate <= max_conversion_threshold

建議預設
	•	min_try_on_threshold = 5
	•	max_conversion_threshold = 0.15

觸發結果

建立 Alert：
	•	alert_type = low_conversion_pattern

備註

這種較偏分析型警示，也可同時產出 Insight

⸻

13.5 staff_assist_recommended

定義

系統判定門市人員可介入協助。

scope_type
	•	session
或
	•	item

觸發條件

可由以下規則之一觸發：
	•	long_dwell 成立
	•	session item_count >= 某門檻
	•	高價值商品停留過久
	•	搭配商品多但未前往 checkout

觸發結果

建立 Alert：
	•	alert_type = staff_assist_recommended
	•	severity = info 或 warning

範例 message
	•	Customer may benefit from styling or size assistance.
	•	Staff follow-up is recommended.

⸻

14. Alert 表產生規則

當符合警示條件時，系統應：
	1.	建立一筆 Alert
	2.	同步建立對應 alert event，例如：
	•	dwell_time_alert
	•	item_left_in_room_alert
	3.	若同類型警示仍為 open，可避免重複建立，改為更新 existing alert

⸻

15. Alert 去重規則

為避免畫面被重複警示洗版，建議實作去重。

15.1 item 型警示去重鍵

可用：
	•	alert_type + item_id + session_id

15.2 session 型警示去重鍵

可用：
	•	alert_type + session_id

15.3 store 型警示去重鍵

可用：
	•	alert_type + store_id + snapshot_window

⸻

16. Alert 狀態流

Alert 建議狀態如下：
	1.	open
	2.	resolved
	3.	dismissed

resolved 條件範例

long_dwell
	•	商品已離開試衣間

item_left_in_room
	•	商品已被移出試衣間

long_session
	•	session 已 completed

17. Demo 模式與實際模式預設值

17.1 Demo mode

17.2 Realistic mode

用於接近實際零售情境。

規則	建議值
long_dwell	900–1800 秒
item_left_in_room	300 秒
long_session	1200–1800 秒
session_idle_close_seconds	300 秒
